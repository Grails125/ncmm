# 云贝活动与短信登录

本分支在保留音乐合伙人评分、推荐歌曲笔记和乐评功能的基础上，接入上游 1.2.10 新增的云贝活动和 WebUI 短信登录。当前改动属于本地开发版本，不代表发布了新的正式版本，也不表示已获得上游完整源码。

## 开启云贝活动

在 WebUI「策略配置 → 日常签到」开启需要的项目。四项默认均关闭，旧账号与音乐合伙人配置不会被新默认值覆盖。

```yaml
sign:
  automatic: true
  yunbeiTask:
    enableRedPacket: false
    enableLottery: false
    enableLotteryWatchVideo: false
    enableWatchVideoYunbei: false
```

| 开关 | 行为 | 默认队列 |
|---|---|---|
| `enableRedPacket` | 查询当前红包雨场次，仅使用服务端已给出的机会，单轮最多六次 | 快任务 `RedPacket` |
| `enableLottery` | 刮刮乐、好运翻卡、扭蛋的已有次数；每次单抽，每个抽奖阶段每种活动最多三十次，不购买次数 | 快任务 `Lottery` |
| `enableLotteryWatchVideo` | 实验性视频增次，并查询首页额外云贝权益；以实际场景和服务端额度为准 | 慢任务 `LotteryWatchVideo` |
| `enableWatchVideoYunbei` | 实验性阶段视频云贝，每轮最多处理十五个阶段 | 慢任务 `WatchVideoYunbei` |

启用某项且两组队列均未包含它时，程序在对应队列末尾追加；现有顺序和音乐合伙人位置保留。所有活动遵守 `task.sign`、主辅账号开关、`sign.automatic` 和 `--only-fast` / `--only-slow`。直接运行 `ncmm sign --automatic` 时处理已开启的活动，不依赖批量队列。

视频增次与抽奖分别控制。若本批次已经执行过启用的抽奖，且该账号云贝活动没有失败或未确认结果，视频阶段结束后会再次查询并处理可用机会；仅执行慢任务或未开启抽奖时保留新增机会。已有未知写回执的活动不会在同一批次重新开启。

红包雨和已有次数抽奖使用独立的 Android XEAPI 客户端，未填写对应 UA 时使用上游发布包中的内置值，仅作用于这些活动。原 Cookie 文件及其他任务的 UA 不会因此改写。

视频任务还需要当前账号配套的 **Android 移动端 Cookie、明确配置的 `network.user_agent.xeapi` 和 `accounts.antiCheatTokens`**。缺少时正常跳过，不使用内置 UA 冒充配套会话；iOS、网页 Cookie 和网页评论 `checkToken` 不能替代这套活动凭据。所有配置都按实际执行账号匹配。

## 结果与恢复

- 等待八至十秒仅对齐上游调用节奏，不代表已实际观看广告或已获得云贝。
- 每次领取、抽奖或权益提交均禁用 HTTP 自动重发；超时不等于服务端未收到。
- 抽奖须核对剩余和已用次数；红包雨须核对领取回执和同场次机会；视频须核对 `gainFlag` 及官方次数或阶段进度。
- 回执缺失、进度未推进或相互矛盾时保留「未确认」，停止本项，不继续消耗次数。普通接口失败记录到任务汇总，其他可执行项目继续；鉴权、限流或取消会停止当前账号的活动请求。
- 次数为零、活动未开放及明确没有素材时正常跳过。日志不伪造成功次数，云贝收益仍读取官方账户流水和余额，不按宣传金额直接累加。
- 活动在同一批次中按账号去重，快慢队列不会重复提交同一活动；新一轮重新读取官方状态。

## WebUI 短信登录

账号中心选择「短信验证」，填写手机号、国家区号和目标账号文件，再获取验证码。发送成功后开始六十秒倒计时；服务端同时限制同号码发送间隔。登录会话五分钟有效，最多五次验证码校验；关闭窗口或切换方式会清理当前临时会话。

登录须通过官方账号身份核对后才保存 Cookie，并沿用配置修订号检查，避免覆盖同时发生的账号修改。失败不会把临时 Cookie 写入已有账号。手机号、验证码、Cookie 及登录请求原文不进入调试日志或配置。

接口需要有效的网易云登录环境；短信未发送、验证码错误、接口拒绝和账号身份无法确认都会明确提示。模拟响应的单元测试和浏览器测试不代表真实短信已送达。

## 协议来源与验证边界

源自 [3899/ncmm v1.2.10 发布包](https://github.com/3899/ncmm/releases/tag/v1.2.10)的静态接口核对，未执行上游程序。Linux x64 包 SHA256 为 `5dc3ce4ea115b14f854e196e0ab9024435f6b0614ea702148fa0c809cf53bfdc`，嵌入源码提交为 `b7f45c84ccb159953007a89fb9f2d6ed2f8853f2`，构建标有 dirty；这与公开文档仓库的提交不同。

云贝活动使用 `interface3.music.163.com/xeapi/` 下的红包雨、抽奖、广告权益和阶段查询接口；短信使用 `interfacepc.music.163.com/eapi/middle/captcha/sent/v1` 与 `/eapi/w/login/cellphone`。实现复用当前项目加密与账号隔离，不以插件或上游可执行文件代跑。

本地 fixture 覆盖请求形态、缺失字段、服务拒绝、不确定写回执、进度核对、取消和次数上限。真实账号的奖励入账、广告场景可用性及短信送达必须以官方实际结果确认。
