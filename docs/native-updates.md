# 本分支的更新与发布

本页说明当前 `Grails125/ncmm` 源码中的实现。音乐合伙人评分、范围配置、各分值乐评、作品日志和本期积分保持不变；插件平台和容器运行时分别见 [插件说明](v129-group3-plugin-platform.md) 与 [Docker 运行时](docker-runtime.md)。

## 单文件程序更新

```bash
ncmm --home ./run update --apply
```

无需事先运行 `ncmm update`。每次主动应用都会先检查本仓库的最新发布；检查失败即返回失败，不使用过期缓存安装。已是最新版本时成功退出并提示无需更新。更新仍只接受本仓库 `-grails.N` 版本及其对应下载路径。

程序目录的更新锁防止不同进程、不同 home 同时替换同一个文件；每个 home 的状态文件还有独立锁。更新包和解压后的程序均限制在 256 MiB 内。程序先写入同目录临时文件、同步并关闭，随后才替换正式文件；状态文件也使用原子替换，保存失败会向调用方返回错误。

Linux/macOS 保留 `.old` 备份后原子替换程序。Windows 先写好临时文件，再将原程序改名为 `.old` 并立即切换临时文件；最后一步失败时尝试恢复原程序。若进程恰在 Windows 的两次改名之间被终止，主程序可能暂时缺失，此时保留 `.old`，确认备份完整后手动恢复原文件名，再执行更新。Python 脚本遇到这种状态会停止，不会误判为首次安装并覆盖恢复文件。

安装状态保存新程序的 SHA-256 指纹，用于识别“文件已安装、进程待重启”。手动降级或替换文件后，旧成功缓存不再阻止更新；两个 home 共用程序且目标文件已经一致时，只补状态回执，保留原备份。指纹用于核对本地安装结果，不是发布签名。

更新成功后，正在运行的 WebUI/任务仍使用原进程，重启后生效。`.old` 不在普通启动或 Python 脚本结束时自动删除，下次替换时才更新备份。

WebUI 系统设置可直接应用更新；安装完成后显示“待重启”和“立即重启生效”，并询问是否立即重启。`updater.auto_restart` 默认开启，后台每 5 秒检查，只有运行、排队和随机延迟任务全部结束后才自动重启；设置为 `false` 可改为手动控制。手动应用更新后保留 30 秒确认时间。重启决定与新任务提交共用同一把锁，决定重启后拒绝新任务进入队列。

手动重启遇到繁忙状态时，服务端返回实时运行与排队数量，需要再次确认后才会停止任务并重启。正在检查或写入更新时拒绝重启。前端通过公开的最小 `/api/v1/instance` 接口每秒探测，只有实例 ID 改变后才刷新，60 秒未恢复则提示检查日志并手动刷新。

容器内更新只对受管理的运行版本开放：需 `NCMM_RUNTIME_MANAGED=1`、有效的 `<NCMM_RUNTIME_DIR>/manager.json`（`{"format":1}`），且程序是 `versions/<slot>/ncmm` 下的普通非空文件；目录默认 `/data/runtime`，拒绝目录内符号链接。普通容器仍使用以下重建方式。启动器的持久化、版本切换及健康回滚由容器运行时负责。

面板 `scripts/ncmm-update.py` 调用同一更新命令，保留原始失败退出码。网络、权限、配置或文件占用失败均不会按进程名称杀死其他 ncmm 任务，也不会自动重试。最终无法读出本分支版本时不报告成功、不写 `VERSION`。

## Docker 更新

使用本仓库 Dockerfile 的受管 Web 容器可通过系统页或 `update --apply` 暂存原生更新，再由 Launcher 重启、健康确认后启用。Compose 默认关闭自动下载，手动更新仍可使用；纯 CLI 模式只使用已确认的 current，暂存后需 Web 模式确认。没有 Launcher 的旧容器需要先重建。源码更新也可继续使用以下方式：

```bash
git pull --ff-only origin main
docker compose build
docker compose up -d
```

Compose 继续挂载原 `data` 目录。源码构建包含原生音乐合伙人功能，不切换到上游分发镜像。

## 发布质量门禁

`Release & Quality Pipeline` 先把标签或手动输入的 ref 解析为固定提交 SHA，调用一次共享的 `quality-checks.yml`；成功后程序包与容器镜像并行构建，均检出并复核该 SHA。质量失败或取消时不发布，移动分支不会使检查和构建使用不同提交。原 `Build Package`、`Build Docker Image` 保留手动入口，仍委托同一门禁流程，只选择相应产物。

门禁包含 Go 测试、vet、竞态检测、Python 更新脚本测试、Node 回归、九组浏览器验证及 Docker 构建检查。手动版本号、指定 ref、正式版/预发布选项继续保留。普通分支和 PR 不发布；只有推送原生发布标签或显式运行发布工作流才创建产物。仓库具备流程不表示已经有可下载的 Release，新安装前需确认发布包存在，否则从源码构建。
