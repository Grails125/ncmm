# 音乐合伙人原生评分

当前版本 `1.2.4-grails` 基于可公开获得的 NCMM v1.2.2 完整源码。评分运行在同一个 Go 主程序中，使用原有账号 Cookie、网络客户端、WebUI、批量任务、调度器和失败通知。无需安装评分插件或 Python 桌面程序。源码来源和版本限制见 [source-baseline.md](source-baseline.md)，许可见 [第三方说明](../THIRD_PARTY_NOTICES.md)。

## Docker 启用

1. 在本分支执行 `docker compose up -d --build`，访问 `http://127.0.0.1:3899`，设置管理密码。
2. 在账号页面登录有音乐合伙人资格的网易云账号。Cookie 需要包含 `MUSIC_U` 与 `__csrf`，过期时应重新登录。
3. 在配置页面的“音乐合伙人评分”设置账号、评分范围、额外任务目标和各分值乐评，再开启批量任务中的“音乐合伙人评分”。初始 `task.music-partner` 为关闭。
4. Compose 的 `CRON_1="30 8 * * * task"` 每天北京时间 08:30 运行配置中已启用的任务。需要不同时间或分开调度时，可删除该环境变量，在原有任务页面创建内置 `music-partner` 任务。避免同时保留重复定时规则。
5. 先通过任务页面手动执行一次，查看运行状态和日志。通知沿用 `notify.yaml` 与全局通知开关。

支持导入已知官方 v1.2.9 及更早配置，迁移前保留备份；未知更高版本或不识别字段会拒绝写回。已有上游实例仍应先备份完整数据，并在独立数据目录验证，不能让两个实例同时操作同一目录。本仓库尚未发布镜像时应按 [Docker 文档](docker.md) 从源码构建，不能换用上游 `3899/ncmm` 镜像。更新二进制仅接受本仓库的 `*-grails` 发布，并兼容历史 `*-grails.N` 版本。

## 命令行

```bash
# 按 musicPartner.enableMain / enableSecondaries 选择账号
ncmm --home ./run music-partner

# 明确执行单个账号（不受批量总开关影响）
ncmm --home ./run music-partner --cookie-file ./run/cookie.json

# 只选择批量任务中的音乐合伙人评分，仍遵守主/副账号开关
ncmm --home ./run task --music-partner

# 执行全部已启用的批量任务
ncmm --home ./run task
```

WebUI 单账号任务使用已有的 `--cookie-file` 参数，调度时会与同一账号的签到等任务互斥。批量任务仍使用原有的保守资源锁。独立从终端启动的多个进程不共享 WebUI 调度锁，不应同时对相同账号执行评分。

## 配置

```yaml
task:
  music-partner: true

musicPartner:
  enableMain: true
  enableSecondaries: false
  scoreMin: 3
  scoreMax: 4
  extraTasks: true
  fullExtraTasks: false
  extraLimitMin: 5
  extraLimitMax: 15
  waitMin: 15
  waitMax: 20
  syncYunCircle: false
  comments:
    "1": []
    "2": []
    "3": []
    "4": []
    "5": []
```

旧版本的自定义快/慢队列会保留。只要启用 `task.music-partner`，新任务会在缺少显式排序项时自动追加到慢任务组；`task --only-fast` 不执行该默认慢任务。

| 配置 | 行为 |
| --- | --- |
| `scoreMin` / `scoreMax` | 每首在上下限之间随机选择整数分，允许 1–5，默认 3–4；上下限相同则固定分值 |
| `comments` | 按 `"1"` 至 `"5"` 配置各分值的乐评列表；每次从对应列表随机取一条，空列表提交空乐评。WebUI 每行一条；每个分值最多 50 条，每条 1–500 字符 |
| `extraTasks` | 是否在基础任务后处理额外作品 |
| `extraLimitMin` / `extraLimitMax` | 额外评分的每日累计目标范围，允许 0–15，默认 5–15；当日目标为 0 时跳过额外评分；同一个平台每日任务 ID 与相同配置始终得到同一随机目标，重复运行只补足差额 |
| `fullExtraTasks: false` | 根据接口返回的已完成记录补到本次每日目标 |
| `fullExtraTasks: true` | 处理本次接口返回的全部待评额外作品，不无限拉取 |
| `waitMin` / `waitMax` | 每次提交前随机等待，单位秒，范围 1–300，默认 15–20 |
| `syncYunCircle` | 是否将评分同步云圈，默认关闭 |

这是按配置范围随机评分，不进行听音、音频质量分析或 AI 音乐评价。乐评只使用用户配置的文本，不自动生成。每日额外进度以平台响应为准；如果平台不再返回完整的当日已完成记录，累计限额语义需要重新适配接口。

启动时自动兼容旧配置：旧 `score` 为 1/2/3 时转换为 1–2/2–3/3–4，为 4 时转换为 4–4；旧 `extraLimit` 在 1–15 内转换为上下限相同的固定目标，超出范围时需手动调整。新的范围字段优先。等待时间沿用原上下限，WebUI 统一使用范围控件。

## 评分前后积分

仪表盘的“账号数据”卡片可独立选择已配置账号，显示当前成长值、VIP 等级、云贝余额，以及音乐合伙人的本期积分、本周积分、期号、周次和北京时间周期范围。进入仪表盘、切换账号、手动刷新或相关任务结束时查询；普通页面渲染和定时状态轮询不会重复请求。各项独立查询，部分不可用不会隐藏其他已取得的数据；未知值不会当作 0。仪表盘使用只读 Cookie 会话，不创建或回写账号文件。

每个账号在评分前、评分结束后各读取一次首页接口的当前本期积分和本周积分，并在任务日志中显示前后值与变化，例如 `本期积分：100 -> 105，变化 +5`。这两次查询复用该账号的同一会话，每次最多等待 15 秒；部分评分失败后仍会查询，查询失败不会改变评分任务原本的成功或失败结果。取消或超时结束的评分不再发起结束查询，日志会注明未查询。

缺失的积分显示为“未知”，不会当作 0。本期差值仅在前后期号完整且相同时计算；本周差值还要求周次完整且相同。跨期、跨周或缺少必要字段时，仍显示已读取的积分，但注明不计算差值。数据使用首页的当前状态，不混用可能属于往期的已结算报告。

日志中的差值是平台账面积分在两次读取间的变化，可能受到结算、调整或其他同时发生的活动影响，不等同于本次任务独占的奖励。差值可以为负；差值为 0 时会提示平台可能延迟入账，不能据此确认没有奖励。

可计算的本期差值会写入任务收益摘要，供“7 日变化”的“合伙人积分”指标与“今日账号收益”汇总；同一天多次执行的差值相加，本周积分不重复计入。旧日志中有明确本期差值的记录也可显示，缺少差值或跨期的记录保持未知。今日账号收益只展示非零的已知变化，余额和成长总值在账号数据卡查看；这里的摘要用于展示，不代表平台已发放额外奖励或新增本地积分账本。

## 失败与恢复

### 今日推荐歌曲、笔记与乐评

`musicPartner.recommendCountMin` / `recommendCountMax` 为每日累计目标范围，均须为非负整数且下限不能大于上限，不设置 3 首的业务上限，默认 0～0 关闭。同一账号、同一北京时间日期及相同范围使用同一随机目标；抽到 0 时跳过新增推荐。旧 `recommendCount` 固定值迁移为相同的上下限，已有模板保持原样。已在 App 完成的歌曲也计入目标；执行数量受平台实际返回的可用推荐歌曲限制，积分按平台结算，超过奖励额度不保证额外积分。原有基础与额外评分继续独立执行，评分额度耗尽不会阻止推荐任务；账号鉴权失败或限流会停止本账号。

```yaml
musicPartner:
  recommendCountMin: 0
  recommendCountMax: 0
  recommendOrder: sequential
  recommendWaitMin: 16
  recommendWaitMax: 20
  recommendNotes: []
  recommendComments: []
```

`recommendOrder` 可选 `sequential`（按推荐列表顺序，默认）或 `random`（随机抽取）。会优先恢复已部分完成的歌曲，再按所选顺序补新歌；同账号同日的相同候选集合使用同一随机顺序，重启不会重新洗牌。发布回执及服务端完成状态继续用于去重。

启用前填写两个独立模板池；每项最多 50 条，每条 1～500 字，支持 `{name}`、`{artist}`，替换后的长度也会校验。等待范围为 16～300 秒。当前用歌曲封面和歌名标题发布公开图文笔记，正文与乐评由配置模板提供；官方 App 的原生封面模板合成器未移植。发布请求复用当前账号会话，可沿用 `accounts.antiCheatTokens` 的短效令牌配置，不读取或复用抓包凭据。

任务先获取推荐音频，再等待配置时长并确认 `PLAY_END` 上报；这不是官方 App 播放器的实际播放验证。笔记、乐评分别取得真实发布 ID 后，才上报 `PUBLISH_EVENT`、`PUBLISH_COMMENT`。仅以服务端完成标记和查询到的积分变化记账；抓包证实两项完成时 `finishTaskNum` 仍可为 2/3，不需要额外收藏。单首基础奖励通常为笔记 2 分、乐评 1 分，实际结果以平台为准。

本功能发布成功的笔记、乐评至少保留 7×24 小时，到期后在下次音乐合伙人任务中自动清理。关闭新增推荐（数量设为 0）仍可清理旧记录，但需要继续运行音乐合伙人任务。记录位于 home 下 `music-partner-recommend/<账号ID>-<日期>.json`，随 Docker `/data` 一起持久化；按账号隔离、使用文件锁和原子写入。只清理本功能已保存真实回执的内容，不扫描或删除手动发布的内容。清理失败下次重试，不在任务中等待七天。

发布前按账号会话与移动端 UA 确定协议：iOS 使用已有 EAPI 兼容路径，Android 使用匹配的 XEAPI UA。协议检查在上传封面和发布意图落盘前完成，不会在写入失败后自动切换协议重发。封面通过网易云 CDN 获取 1080 尺寸版本，减少大图的图片处理超时；上传失败记录具体阶段、分类及数值状态。日志保留所选协议、受控的失败阶段、HTTP 状态和服务码，不输出凭据或原始响应。

本地参数或协议检查明确尚未发出发布请求时，保留为可继续执行状态；已经发出但结果不明时保留意图记录并停止自动重发；已取得 ID 但上报失败时下次只补上报。若平台尚未回写完成状态，需要在 App 核对，不能把未确认的发布当作成功。端点、来源和成功计分链来自用户提供的成功抓包及官方 H5；原生 C/R/S 请求体未完整恢复，客户端适配沿用仓库既有发布模型，离线测试不等于真实账号发布验收。

- 每次执行读取平台任务进度，跳过已完成作品。额外作品先提交播放完成报告，报告成功才提交评分。
- 网络写入失败不自动重投。先查询一次完成状态；无法确认时返回失败，避免把结果未知的提交当作成功。
- 未登录、无资格、频率限制、无效响应、资源报告失败与部分评分失败会进入失败日志和通知汇总。单独命令以及包含评分的批量命令返回非零退出码，WebUI 显示失败。
- 平台返回 405 且消息为“今日没有更多可评定歌曲啦”时，停止本次评分且不自动重试，记录为当日可评歌曲已用尽，不标记账号风控；未完成的额外目标仍报告失败。
- 未达到每日目标且当前候选作品不足时，记录实际完成数量并报告目标未完成；选择“完成当前全部额外任务”时则以返回列表为目标。
- 取消任务会中止等待和 HTTP 请求。已经被平台接受的提交不会因本地取消而撤回，下次运行会重新查询。
- 任务运行到北京时间次日零点时会停止当前快照，避免将前一天任务 ID 用于新一天的评分；下次调度重新读取任务。
- 评分请求强制证书校验、有限超时和禁止自动 POST 重试；即使开启全局调试，也不记录评分请求的 Cookie、CSRF 或原始响应。
- 评分与播放上报按参考实现发送数字 ID；评分开关使用字符串，未使用的 `source`、`syncComment`、`extraScore` 不发送。`syncYunCircle` 仍遵守本地配置，关闭时不会因兼容调整自动开启。
- 日志分别记录每日任务读取、额外任务读取、播放结束上报、评分提交和结果核对阶段，每行包含时间，并显示作品名、作者、作品 ID、分值、乐评和脱敏后的评分请求。响应日志保留服务码、脱敏消息及评分结果字段，`data: null` 保留为空而不伪造为零值结果；Cookie、CSRF、令牌、完整 URL 和未知响应字段不写入日志。无明确原因的 405/460 显示“请求被拒绝，具体原因未确认”，不直接断定为风控。

仓库测试使用模拟接口与隔离数据目录；不包含真实账号的资格、实时接口可用性、实际评分入账或云圈同步验收。
