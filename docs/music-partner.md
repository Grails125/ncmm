# 音乐合伙人原生评分

当前版本 `1.2.2-grails.1` 基于可公开获得的 NCMM v1.2.2 完整源码。评分运行在同一个 Go 主程序中，使用原有账号 Cookie、网络客户端、WebUI、批量任务、调度器和失败通知。无需安装评分插件或 Python 桌面程序。源码来源和版本限制见 [source-baseline.md](source-baseline.md)，许可见 [第三方说明](../THIRD_PARTY_NOTICES.md)。

## Docker 启用

1. 在本分支执行 `docker compose up -d --build`，访问 `http://127.0.0.1:3899`，设置管理密码。
2. 在账号页面登录有音乐合伙人资格的网易云账号。Cookie 需要包含 `MUSIC_U` 与 `__csrf`，过期时应重新登录。
3. 在配置页面的“音乐合伙人评分”设置账号、评分范围、额外任务目标和各分值乐评，再开启批量任务中的“音乐合伙人评分”。初始 `task.music-partner` 为关闭。
4. Compose 的 `CRON_1="30 8 * * * task"` 每天北京时间 08:30 运行配置中已启用的任务。需要不同时间或分开调度时，可删除该环境变量，在原有任务页面创建内置 `music-partner` 任务。避免同时保留重复定时规则。
5. 先通过任务页面手动执行一次，查看运行状态和日志。通知沿用 `notify.yaml` 与全局通知开关。

已有较新上游实例请先备份并使用新的数据目录；程序会拒绝将大于 v1.2.2 的配置自动降级写回。本仓库尚未发布镜像时应按 [Docker 文档](docker.md) 从源码构建，不能换用上游 `3899/ncmm` 镜像。更新二进制仅接受本仓库的 `*-grails.N` 发布。

## 命令行

```bash
# 按 musicPartner.enableMain / enableSecondaries 选择账号
ncmm --home ./run music-partner

# 明确执行单个账号（不受批量总开关影响）
ncmm --home ./run music-partner --cookie-file ./run/cookie.json

# 只选择批量任务中的音乐合伙人评分，仍遵守主/副账号开关
ncmm --home ./run task --music-partner

# 执行全部已启用的批量任务
ncmm --home ./run task
```

WebUI 单账号任务使用已有的 `--cookie-file` 参数，调度时会与同一账号的签到等任务互斥。批量任务仍使用原有的保守资源锁。独立从终端启动的多个进程不共享 WebUI 调度锁，不应同时对相同账号执行评分。

## 配置

```yaml
task:
  music-partner: true

musicPartner:
  enableMain: true
  enableSecondaries: false
  scoreMin: 3
  scoreMax: 4
  extraTasks: true
  fullExtraTasks: false
  extraLimitMin: 7
  extraLimitMax: 7
  waitMin: 15
  waitMax: 20
  syncYunCircle: false
  comments:
    "1": []
    "2": []
    "3": []
    "4": []
    "5": []
```

旧版本的自定义快/慢队列会保留。只要启用 `task.music-partner`，新任务会在缺少显式排序项时自动追加到慢任务组；`task --only-fast` 不执行该默认慢任务。

| 配置 | 行为 |
| --- | --- |
| `scoreMin` / `scoreMax` | 每首在上下限之间随机选择整数分，允许 1–5，默认 3–4；上下限相同则固定分值 |
| `comments` | 按 `"1"` 至 `"5"` 配置各分值的乐评列表；每次从对应列表随机取一条，空列表提交空乐评。WebUI 每行一条；每个分值最多 50 条，每条 1–500 字符 |
| `extraTasks` | 是否在基础任务后处理额外作品 |
| `extraLimitMin` / `extraLimitMax` | 额外评分的每日累计目标范围，允许 1–500，默认 7–7；同一个平台每日任务 ID 与相同配置始终得到同一随机目标，重复运行只补足差额 |
| `fullExtraTasks: false` | 根据接口返回的已完成记录补到本次每日目标 |
| `fullExtraTasks: true` | 处理本次接口返回的全部待评额外作品，不无限拉取 |
| `waitMin` / `waitMax` | 每次提交前随机等待，单位秒，范围 1–300，默认 15–20 |
| `syncYunCircle` | 是否将评分同步云圈，默认关闭 |

这是按配置范围随机评分，不进行听音、音频质量分析或 AI 音乐评价。乐评只使用用户配置的文本，不自动生成。每日额外进度以平台响应为准；如果平台不再返回完整的当日已完成记录，累计限额语义需要重新适配接口。

启动时自动兼容旧配置：旧 `score` 为 1/2/3 时转换为 1–2/2–3/3–4，为 4 时转换为 4–4；旧 `extraLimit` 转换为上下限相同的固定目标。新的范围字段优先。等待时间沿用原上下限，WebUI 统一使用范围控件。

## 评分前后积分

仪表盘提供“音乐合伙人积分”卡片，可独立选择已配置账号，显示本期积分、本周积分、期号、周次、北京时间周期范围和查询时间。进入仪表盘、切换账号、点击“刷新积分”或相关任务结束时查询；普通页面渲染和定时状态轮询不会重复请求。查询失败时已有积分保留并标记过期，未获取的数据显示“未知”。仪表盘使用只读 Cookie 会话，不创建或回写账号文件。

每个账号在评分前、评分结束后各读取一次首页接口的当前本期积分和本周积分，并在任务日志中显示前后值与变化，例如 `本期积分：100 -> 105，变化 +5`。这两次查询复用该账号的同一会话，每次最多等待 15 秒；部分评分失败后仍会查询，查询失败不会改变评分任务原本的成功或失败结果。取消或超时结束的评分不再发起结束查询，日志会注明未查询。

缺失的积分显示为“未知”，不会当作 0。本期差值仅在前后期号完整且相同时计算；本周差值还要求周次完整且相同。跨期、跨周或缺少必要字段时，仍显示已读取的积分，但注明不计算差值。数据使用首页的当前状态，不混用可能属于往期的已结算报告。

日志中的差值是平台账面积分在两次读取间的变化，可能受到结算、调整或其他同时发生的活动影响，不等同于本次任务独占的奖励。差值可以为负；差值为 0 时会提示平台可能延迟入账，不能据此确认没有奖励。这里不新增积分事件或本地入账记录。

## 失败与恢复

- 每次执行读取平台任务进度，跳过已完成作品。额外作品先提交播放完成报告，报告成功才提交评分。
- 网络写入失败不自动重投。先查询一次完成状态；无法确认时返回失败，避免把结果未知的提交当作成功。
- 未登录、无资格、频率限制、无效响应、资源报告失败与部分评分失败会进入失败日志和通知汇总。单独命令以及包含评分的批量命令返回非零退出码，WebUI 显示失败。
- 平台返回 405 且消息为“今日没有更多可评定歌曲啦”时，停止本次评分且不自动重试，记录为当日可评歌曲已用尽，不标记账号风控；未完成的额外目标仍报告失败。
- 未达到每日目标且当前候选作品不足时，记录实际完成数量并报告目标未完成；选择“完成当前全部额外任务”时则以返回列表为目标。
- 取消任务会中止等待和 HTTP 请求。已经被平台接受的提交不会因本地取消而撤回，下次运行会重新查询。
- 任务运行到北京时间次日零点时会停止当前快照，避免将前一天任务 ID 用于新一天的评分；下次调度重新读取任务。
- 评分请求强制证书校验、有限超时和禁止自动 POST 重试；即使开启全局调试，也不记录评分请求的 Cookie、CSRF 或原始响应。
- 评分与播放上报按参考实现发送数字 ID；评分开关使用字符串，未使用的 `source`、`syncComment`、`extraScore` 不发送。`syncYunCircle` 仍遵守本地配置，关闭时不会因兼容调整自动开启。
- 日志分别记录每日任务读取、额外任务读取、播放结束上报、评分提交和结果核对阶段，每行包含时间，并显示作品名、作者、作品 ID、分值、乐评和脱敏后的评分请求。响应日志保留服务码、脱敏消息及评分结果字段，`data: null` 保留为空而不伪造为零值结果；Cookie、CSRF、令牌、完整 URL 和未知响应字段不写入日志。无明确原因的 405/460 显示“请求被拒绝，具体原因未确认”，不直接断定为风控。

仓库测试使用模拟接口与隔离数据目录；不包含真实账号的资格、实时接口可用性、实际评分入账或云圈同步验收。
